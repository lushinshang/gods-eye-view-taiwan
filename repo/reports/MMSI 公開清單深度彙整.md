# 公開情資能補到海警艦隊三成,官方原始來源幾乎空白

深度彙整 AMTI/CSIS、C4ADS、Global Fishing Watch、日本總務省、中國各海洋機構官網與 ITU MARS 後,答案是:公開情資能靠智庫報告建立起一份**具名、具 MMSI、可追溯出處**的中國「海上民兵/漁船」對照表(C4ADS/AMTI 2021 年報告,**122 艘「已確認」+ 52 艘「疑似」民兵船**,附完整船名/MMSI/所有人),但對使用者真正想要的**中國海警船本身**,目前查無任何智庫或官方機構公開發布過一份系統性的船名對照 MMSI 清單——所有海警船 MMSI(包括已知集中在 413875xxx 子區段的那批)全部只能從 MagicPort、VesselFinder、TradLinx、Maritime Optima 等**商業 AIS 聚合站**取得,這些站點彼此之間還存在實質衝突(同一艘 CCG1104 在兩個聚合站上各自標示 413875024 與 413213000)。日本海上保安廳的狀況更貧乏:JCG 官網公布的是艇種名錄與年度艦隊總數,完全不含 MMSI 或呼號;日本總務省確實存在一個法定公開的無線電執照查詢系統(電波利用ポータル的「無線局等情報検索」),理論上是**唯一一個已知、對船舶 MMSI 具有法律約束力的一手政府資料庫**,但本次研究未能成功以互動方式查詢,也未確認政府船是否會出現在這個對民用無線電執照設計的系統裡。中國科考船同樣只有零散的機構新聞稿(廈大「嘉庚」號、中科院「科學」號等各自的規格頁),沒有任何中國官方機構(自然資源部、中國海事局、工信部)公布過船名對應 MMSI 的清單。整體而言,公開情資能把**漁船民兵**這一類補到接近研究級(C4ADS 附錄),但對**海警船、海保船、科考船**這三類,公開情資的「天花板」仍然是商業聚合站的二手資料,真正具約束力的一手來源(ITU MARS、各國電信主管機關的船台執照資料庫)理論上存在,但實務上都因為互動式表單/JS 渲染而難以批量取用,也未被任何研究驗證是否真的收錄政府船。

## C4ADS/AMTI 的 2021 年報告是唯一達到「研究級」的具名清單,但只覆蓋民兵漁船

真正查到、下載、解密並逐行比對過原始 PDF 之後,目前可確認的最佳公開清單是 **C4ADS 與 CSIS/AMTI 聯合發布的 2021 年報告《Pulling Back the Curtain on China's Maritime Militia》**,其附錄 A、B 以表格形式列出 `船名 | 登記城市 | MMSI | 直接所有人 | 最終受益人` 五欄資料,附錄 A 收錄 **122 艘「已確認」民兵船**、附錄 B 收錄 **52 艘「疑似」民兵船**,合計約 169-174 艘,逐艘附帶具名責任人與國企/地方財政局等所有權鏈([C4ADS PDF](https://c4ads.org/wp-content/uploads/2021/11/PullingBacktheCurtain-Report.pdf);[AMTI 落地頁](https://amti.csis.org/pulling-back-the-curtain-on-chinas-maritime-militia/))。這份清單的可信度明顯高於商業聚合站,因為它附帶完整的方法論與第三方可驗證的所有權鏈條,而不只是一個裸的「船名-MMSI」配對;2024 年 AMTI 又發布後續文章,宣稱已把海南民兵船清單從 69 艘擴充到 **152 艘**,並承諾附上「船名、MMSI、辨識信心等級」的表格,但本次研究直接抓取該頁面原始 HTML(599 行渲染 / 66KB 原始碼)後確認**那份表格並未出現在靜態頁面中**,極可能是用戶端 JavaScript 動態載入或已經下架,需要瀏覽器自動化工具才能確認是否仍存在([AMTI 2024 文章](https://amti.csis.org/behind-the-curtain-an-update-on-hainans-maritime-militia/))。這份報告的致命限制是**範圍完全不含海警船**——AMTI 自己發布的海警巡邏追蹤系列報告(「Flooding the Zone」「Control by Patrol」等年度報告)只公開「某礁岩周邊某海警船出現了多少天」的彙總統計數字,從未附上逐艘海警船的 MMSI 對照表;也不含科考船——AMTI 的「印太研究船調查」文章只具名列出向陽紅系列、雪龍等船名,文章內文完全沒有附 MMSI 或 IMO 編號([AMTI 研究船文章](https://amti.csis.org/a-survey-of-marine-research-vessels-in-the-indo-pacific/))。換句話說,C4ADS/AMTI 這套研究級方法論已經證明可以做出來,但他們自己選擇只對**漁船民兵**這一類船種做到底,對使用者真正關心的海警、科考、海保三類完全沒有同等深度的公開產出。

## CSIS Futures Lab 的研究船報告有方法論但數據被鎖在圖片裡,ITU MARS 理論上最權威卻打不開

除了 C4ADS/AMTI 那份報告,另一份值得注意的是 **CSIS Futures Lab 的《China's Weaponization of Dual-Use Research Vessels for Undersea Data Dominance》**,其方法論明確寫出:以美國德拉瓦大學「International Research Vessel Schedules & Information」資料集為起點,逐艘對照 MarineTraffic.com 核實船種與 MMSI,再用 General Atomics 的 Optix 平台查詢 2020-2025 年的 AIS 軌跡,最終產出涵蓋 **48 國、223 艘**研究船的資料集([CSIS 報告](https://www.csis.org/analysis/chinas-weaponization-dual-use-research-vessels-undersea-data-dominance))。這份報告有兩個關鍵問題:第一,它的底層 MMSI 來源仍然是 MarineTraffic 這個商業聚合站,並非獨立於商業資料的一手驗證;第二,附錄 A1-A4、B1 的逐船清單是**以圖片形式嵌入 PDF**,本次研究以一般網頁抓取工具無法把圖片中的文字轉為可查詢的資料,需要額外的 OCR 或人工謄寫才能還原成表格——這代表即便這份報告存在,它目前對外呈現的形式仍不是「可直接匯入資料庫」的開放資料集。真正讓人意外的發現是:**全球唯一一個由聯合國機構(ITU)直接維運、對 MMSI 分配具權威性的公開查詢系統確實存在**,叫做 **ITU MARS(Maritime mobile Access and Retrieval System)**,由 ITU 無線電通信局根據各國電信主管機關的申報即時更新,可依船名、呼號、MMSI、IMO 編號查詢([ITU MARS](https://www.itu.int/en/ITU-R/terrestrial/mars);[US Coast Guard NAVCEN 說明](https://www.navcen.uscg.gov/node/33030))。本次研究直接測試了查詢(`https://www.itu.int/mmsapp/ShipStation/list?shipName=XUE+LONG` 301 轉址到 `mmsapp.itu.int`),但該頁回應「未提供查詢條件」,顯示其查詢介面是 JS/POST 驅動的表單,單純的 GET 查詢字串打不進去——這代表 ITU MARS 雖然是理論上最權威的一手來源,**本次研究未能驗證中國海警船或科考船是否真的會出現在裡面**(各國申報哪些船台給 ITU 本身是一個開放問題,政府/軍警船是否照常申報、申報資料是否對外公開檢索,都未經確認)。日本總務省的「無線局等情報検索」系統情況類似:法源明確(電波法第 25 條,2002 年修法後公開),且有正式文件化的 JSON/XML/CSV Web API([總務省 API 說明](https://api-catalog.e-gov.go.jp/info/en/apicatalog/view/46)),但本次研究只確認了導覽路徑與 API 文件存在,**未實際成功查詢過任何一艘具名 JCG 船隻**,也不確定政府船舶電台是否被列入這個主要為民用船舶執照設計的系統,留下一個有潛力但未驗證的缺口。

## 商業聚合站是目前海警船與科考船 MMSI 的唯一實際來源,且彼此互相矛盾

扣除掉上述少數研究級清單,本次研究反覆得到的結論是:**中國海警船、中國科考船、日本海保船的 MMSI,目前在公開網路上只能從商業 AIS 聚合站取得**——MagicPort、VesselFinder、TradLinx、Maritime Optima 是反覆出現的四個站點,沒有一個站點公開其資料來源方法論或與官方登記資料的對帳機制。具體衝突案例包括:**CHINACOASTGUARD1104** 在 MagicPort 上分別被標示 413875024 與 413213000 兩個不同 MMSI,對應同一艘船([來源 A](https://magicport.ai/vessels/special-craft/china-coastguard1104-mmsi-413875024);[來源 B](https://magicport.ai/vessels/tugs-harbor-craft/china-coastguard1104-mmsi-413213000));**CHINACOASTGUARD5901** 在不同站點間也出現 413875411 vs 413482360 的矛盾,對應同一個 IMO 編號;中國科考船「雪龍號」出現 412863000(VesselFinder/VesselTracker)與 412018330(MagicPort/Maritime Optima)兩個版本,兩邊甚至連船型分類(破冰船 vs 雜貨船)都不一致;「大洋一號」同樣有 412017140 與 412923000 兩版,僅能用「最後一次 AIS 回報時間」的新舊做弱推論,無法確認哪個是現行值;「實驗 3 號」則只找到 413621760 一個版本,使用者原先懷疑存在的 412988000 完全查無出處,不排除是誤記或屬於另一艘同名/相似船。這些衝突不是單一站點的疏漏,而是整個商業聚合站生態系統的結構性問題——它們各自用不同的 AIS 接收網路與歷史資料拼接船籍資料庫,沒有一家對外說明如何處理「同一 MMSI 被兩艘不同船使用」或「船換了 MMSI 但資料庫沒更新」這類已知的 AIS 資料品質問題。日本海保船的 11 艘抽樣資料也完全來自 MagicPort 等聚合站,JCG 官網本身在「船艇」頁面只列出代表性船名與艇種圖示,從未公布 MMSI 或呼號([JCG 船艇頁](https://www.kaiho.mlit.go.jp/soubi-yosan/sentei/ship.html))。

## 對 gods-eye-view 的務實建議:分船種訂定不同信心等級,且接受海警船缺口無法靠公開情資完全補上

綜合以上,若 gods-eye-view 要維護一份人工核實的 MMSI 對照表,三類船種應該採取不同策略,而不是一體適用。**漁船民兵**類應以 C4ADS/AMTI 2021 年報告的附錄 A、B 為主幹,這是目前唯一附帶完整所有權鏈、可獨立驗證的研究級清單,可以標示為「高信心」;若要擴充,下一步應嘗試用瀏覽器自動化工具重新抓取 2024 年「Behind the Curtain」頁面,確認那份 152 艘海南民兵船表格是否真的以 JS 動態載入,這是本次研究唯一明確留下、且有具體下一步可做的缺口。**中國海警船**本身目前沒有任何研究級公開清單,務實做法是直接沿用商業聚合站資料,但必須對每一艘海警船要求至少兩個獨立聚合站互相印證,凡是衝突(如 CCG1104、CCG5901)一律標示為「未決、需人工複核」而非選一個「看起來對」的值;同時應把 413875xxx 子區段規則保留為 UI 上的「低信心提示」,而非自動核實依據,這點與先前 MMSI 規範研究報告的建議一致。**中國科考船與日本海保船**的缺口最大且最難補——科考船只能靠機構官網的船隻介紹頁(廈大「嘉庚」號、中科院「科學」號等)取得規格與沿革,完全沒有 MMSI;海保船則完全依賴商業聚合站,JCG 官方管道不提供任何身分識別碼。這兩類若要提升可信度,理論上唯二的突破口是 **ITU MARS** 與日本總務省的「無線局等情報検索」Web API,但兩者都需要具備 JS 表單互動或 API 金鑰申請能力的後續研究才能驗證「政府船是否真的被收錄其中」——在未驗證之前,不應假設這兩個系統能解決問題。最後,所有清單都必須正視一個結構性限制:中國海警船與科考船已有多筆具名、具時間地點紀錄的 AIS 偽造案例(2023 年仁愛礁事件廣播假 MMSI 412000000、2026 年「佳海科 7」被指控偽造位置),這代表即便建成一份完美核實的對照表,船隻本身仍可能在特定任務時主動偽造或關閉 AIS,任何自動比對結果都應保留「無法比對不代表不是該船」的空間。

## 結論

這次深度彙整最關鍵的發現,是公開情資的覆蓋能力在三類船種之間呈現**斷崖式落差**:漁船民兵有 C4ADS/AMTI 這種附完整所有權鏈的研究級資料,海警船、科考船、海保船則全數退回到彼此矛盾的商業聚合站,連名義上最權威的 ITU MARS 和日本總務省查詢系統,都因為互動介面的技術門檻而未被任何公開研究實際驗證過是否收錄政府船。這意味著 gods-eye-view 若要做出「更權威」的對照表,靠彙整現有智庫報告能做到的提升相當有限——真正的瓶頸不是情資彙整技巧,而是中國海警局、中國海事局、日本總務省這些真正持有一手登記資料的機關,從未以任何形式公開完整名冊,智庫與商業聚合站填補的只是這個空白的邊緣,核心仍是空的。下一步最有實證價值的行動,不是再找更多商業聚合站交叉比對,而是用具備表單互動能力的工具去實測 ITU MARS 與日本総務省 API 能否真的查到具名政府船——這是本次研究唯一指出「有希望但未驗證」的方向,其餘管道已經可以確定碰到天花板。
