# windows-ais-capture.ps1 — 誠實告知

這支腳本是給沒有 Node.js、也沒有系統管理員權限裝軟體的 Windows 機器，用來獨立擷取台灣 MOTC 船舶 AIS 資料存檔。寫之前已經實測過 API 本身回得來、格式正確，但以下幾點**還沒有驗證過**或**有意跟主程式不一樣**，使用前務必知道。

## 未驗證

- **沒有在真正的 Windows 環境跑過**。撰寫環境是 macOS，沒有 PowerShell 可以做語法檢查，邏輯是依照實測拿到的真實 API 回應手寫的，但程式本身從未執行過。第一次跑的時候請盯著 `wrote N rows` 這行輸出，並確認 `D:\trace\` 底下真的生出 `.ndjson` 檔案，再放心讓它背景跑。
- **去重邏輯用的是記憶體內的狀態**（`$lastPoints` 這個 hashtable），只要腳本重啟（排程器重試、電腦重開機）就會清空，重啟後第一輪可能會多寫一筆跟前一筆幾乎一樣的資料。無害，但解釋了為什麼檔案裡偶爾會出現間距異常短的重複點。

## 跟主程式刻意不同的地方

- **`k` 欄位不是分類標籤**：這裡存的是 MOTC 原始的 `Ship_and_Cargo_Type` 數字代碼，不是主程式 `classifyVesselAgency()` 算出來的「中國海警/科考船」這類人看得懂的分類。要做那層分類，之後要另外拿這份原始資料跑一次對應的分類邏輯，這支腳本本身不做。
- **沒有保留天數限制**：主程式的 `taiwan-tracks.js` 會自動清掉超過 7 天的檔案，這支腳本**沒有任何清理機制，會無限累積下去**。長期放著跑，`D:\trace` 的容量會一路長大，沒有上限保護，要自己定期檢查或手動清。

## 這支腳本本身沒處理的事（需要另外設定）

- **不會自動在開機時啟動**：腳本只負責跑起來之後自己無限迴圈，啟動它這件事要靠 Windows 工作排程器設定「開機時」「登入時」兩個觸發，之前討論過的設定還沒做成自動化。
- **不會自動重開機後恢復**：如果電腦重開機或腳本意外中斷，不會自己重新啟動，要靠工作排程器的「如果工作失敗，重新啟動」設定來補。
- **沒有防止電腦睡眠**：睡眠設定要照之前討論的，去系統設定裡手動改，這支腳本不會幫你關睡眠。

## 已知但判斷可以接受的風險

- **MOTC 會擋雲端機房 IP**：已實測確認（Google Cloud e2-micro VM：DNS 解析正常但 TCP 連線 timeout），所以這支腳本**只能在住宅或公司這類一般網路的機器上跑**，放到任何雲端 VM 上大概率會失敗。
- **公司電腦的不確定性沒有解決**：IT 政策是否允許、Windows Update 會不會強制重開機、電源設定是否被 Group Policy 鎖死，這些都還沒有確認答案，取決於你實際測試的結果。
