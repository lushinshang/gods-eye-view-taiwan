01

專案願景與設計哲學

海事與空域的公開訊號（AIS、ADS-B、TLE 軌道根數、交通 CCTV）本來就存在，但長期散落在各自封閉的網站與相異格式中。本專案的目標只有一件事：讓指揮官與研究員在同一個統一視野中，從「整個臺灣海峽的宏觀態勢」一路下鑽至「單一船隻的 MMSI、航速、航向與泊位」，不切換工具、不離開地球。

系統全景與雙軌數據架構

全系統採用單一 Vite Dev Server 結合高效能中介層（Middleware Proxy），兼具前端靜態資源交付與後端安全代理：

全系統運行全景（630km 視角） 左側為全域大盤，右側為航港局專屬動態台，海峽航道開闊清爽。
近景港口泊位展開（45km 特寫） 拉近至高雄港外海時，港內所有停泊船隻細膩展開，仍維持 13px 比例。

🛡️ 後端雙軌數據代理與記憶體快取防護

  • 安全長連線防護：由後端統一代管標頭（Referer、User-Agent）與 CORS 跨域處理，瀏覽器不直接衝擊政府主機。
  • 40 秒記憶體快取（In-Memory Cache）：航港局 GeoJSON 單次達 3.6 MB，後端以 _fetchingPromise 機制合併同一時間內的併發請求，嚴格每 40 秒才向上游拉取一次。
  • 優雅降級（Graceful Fallback）：若上游伺服器瞬斷或維護，後端保留上一份有效快取（rows.length > 0 才覆寫），確保 3D 地球畫面絕不瞬間清空。
  • 本機安全綁定：Docker 預設嚴格綁定在 127.0.0.1:4173，防止伺服器代管的私有金鑰意外暴露於區網。
03

一鍵啟動：run.sh / Docker + uv

⚡ 0. 極速一鍵啟動（推薦首選）

在專案根目錄執行專屬 Shell 腳本，自動檢查 Docker、拉起背景容器、健康檢查並自動開啟瀏覽器；欲停止時在終端機按下 [Ctrl + C] 即自動安全關閉 Docker 容器：

# 專案根目錄下直接執行 (按 Ctrl+C 可一鍵優雅退出)
./run.sh

🐳 1. Docker Compose 容器化啟動

無需安裝複雜的 Node.js 或前端依賴，一行指令即可拉起生產級環境：

# 進入原始庫目錄並啟動容器
cd repo
docker compose up -d --build

# 容器就緒後，在瀏覽器打開：
# 👉 http://127.0.0.1:4173

* 容器以當前使用者的 UID:GID 執行，所有設定與快取目錄（.gev-cache）直接映射回本機，無 Root 權限衝突。

🔍 2. uv 隔離式自動化驗收測試

採用現代 Python 套件管理器 uv，支援 PEP 723 內嵌宣告，零全域依賴污染一鍵執行完整的 Playwright 探針套件：

# 在專案目錄執行（uv 自動建立隔離沙盒並下載 Playwright 驅動）
uv run verify_gev.py

測試腳本將自動檢測：

  • 後端端點：/api/vessels、/api/taiwan-vessels、CCTV 與衛星。
  • 前端 WebGL：Cesium Canvas 渲染、GLSL 後製著色器（NVG / FLIR）與快捷鍵。
  • 自動產出驗收報告至 test-results/report.json 與高解析度實機截圖。

答案：全系統 100% 背景靜默更新，完全不需要手動 Reload！

🗺️ 5. 右側戰情台功能總覽

🧭 6. 歷史航跡（6h／24h／7d 切換與 🎥 飛覽）

  1. 選船：點擊海面上的船，單船卡片下方會出現航跡區，3D 地球同時畫出船型色折線。
  2. 切換時段：按 6h、24h（預設）或 7d。切換後自動重抓，舊請求會取消；選定的時段在換船後保留。
  3. 看統計：顯示「點數／里程／跨度」。資料超過 2,000 點會標「（已抽稀）」。
  4. 🎥 飛覽航跡：至少 2 點時才出現，按下後鏡頭以 1.5 秒垂直俯視整段航跡。
  5. 離開：取消選取或換船時，折線自動清除。

航跡只包含伺服器運行期間累積的資料。7d 需要累積滿 7 天才有完整範圍；非 9 位數字 MMSI 的船不會入庫。

🧠 7. AI 參謀（think 開關、Citations、PAT）

  1. 確認燈號：標題旁顯示模型名稱代表就緒；「模型未就緒」表示本機沒有對應模型；「Ollama 未連線」表示服務未啟動。
  2. 提問：按快捷按鈕「📊 海陸態勢總結」「🚢 高雄港油輪動態」「🛣️ 國道壅塞與事故」，或自行輸入（上限 2,000 字）。已選取船舶或事件時，提問會帶入該目標。
  3. 🧠 深度研判（think）：勾選後啟用模型思考模式，輸出預算由 1,024 提高到 2,048。思考內容不會顯示。本機推論通常需要數十秒。
  4. 判讀結果：「✔ 已通過 Grounding 核驗」代表回答中的 MMSI、船名與數字都能回溯資料；「已降級為確定性簡報」代表改用程式產生的簡報，括號內是原因。
  5. 📚 Citations：展開可看資料健康度、符合筆數，以及模型實際讀到的船舶、事件與路段。
降級原因含意處理方式
grounding_failed模型回答未通過核驗或被截斷簡報內容可直接使用；可換個問法重試
ollama_unavailableOllama 或模型無法使用啟動 Ollama，確認已有 gemma4:e4b

同時只能一筆推論，其他請求會收到忙碌回應，稍候再試。Validator 能確認數值可回溯，但無法保證數值與對象的配對，重要判斷請對照 Citations。

🔐 PAT 權杖管理（僅外部程式需要）

  1. 本機瀏覽器使用戰情台不需要 PAT。
  2. 展開「🔐 PAT 權杖管理」，按「產生新權杖」。權杖只顯示這一次，請立即按「複製」保存；之後只看得到指紋。
  3. 按「重新產生」會讓舊權杖失效；按「撤銷」會刪除權杖。
curl -X POST http://localhost:4173/api/taiwan-ai-advisor \
  -H "Authorization: Bearer $GEV_PAT" \
  -H "Content-Type: application/json" \
  -d '{"query":"高雄港附近的油輪動態如何？","think":false}'

PAT 為唯讀：可呼叫 advisor 與 status，無法產生或撤銷權杖。

🛣️ 8. 路況開關與徽章

  1. 開啟：勾選「🛣️ 臺灣即時路況與事件 (TISV/警廣)」。開啟後每 60 秒自動更新，關閉時清除地圖圖元並停止更新。
  2. 讀徽章：事故、施工、壅塞、管制、其他五類，各自顯示目前件數。
  3. 讀摘要：「國道均速 N km/h・壅塞路段 A（≤40）／B（≤70）」，A 是嚴重壅塞路段數，B 是車速 41–70 km/h 的路段數。
  4. 看地圖：路段小色點為紅（≤ 40）、黃（≤ 70）、綠；順暢路段拉近才顯示。事件是帶白框的大色點，事故最大。
  5. 看詳情：點選路況圖元時，卡片顯示描述、道路、方向、車速、來源、座標與時間。

「路況載入失敗」會顯示在開關下方。上游全部失敗時，系統仍回傳上一次成功資料。警廣 PBS 失聯時事件只來自高公局 TISVCloud，端點恢復後最久 1 小時才重試。路況圖元的點擊在無頭瀏覽器尚未實證，操作以實機畫面為準。

常見問題與排錯指南 (FAQ)

Q1. 地球上完全看不到任何臺灣船隻？

請先在終端機執行 curl http://127.0.0.1:4173/api/taiwan-vessels。若回傳總數正常（> 9,000 艘），請檢查右側面板母開關「即時船舶位置」是否打勾，並確認視角已聚焦於臺灣海域（停泊小船在視距 > 280km 時自動抽稀隱藏）。

Q2. 船隻位置會瞬間「跳格」？

這是正常物理現象。AIS 船舶數據為真實岸基雷達觀測值（每 40 秒刷新一次階梯更新），而非虛擬線性內插。每艘船的位置均以該船實際發射 AIS 廣播時的精確經緯度為準。

Q3. 為什麼「未具體說明」的船隻佔比高達 4,000 多艘？

這是臺灣近海真實狀況。大量近岸小舢舨、無動力駁船或小型漁船在安裝 AIS 時，應答機類型碼填寫為 0 或留空。系統忠實依據航港局原始資料歸入「未具體說明的船舶」，不主觀猜測。型號 33（作業／水中作業船，約 62 艘）已改歸「引水船、搜索船、拖駁船等」，因此實測未具體說明約 4,510 艘（歸類前 4,593 艘）。

Q4. 執行 uv run verify_gev.py 報告 Chromium 驅動遺失？

Playwright 首次執行需下載瀏覽器 headless shell。請執行 uv run --with playwright playwright install chromium 即可自動補全。
